# Caliber Learnings

Accumulated patterns and anti-patterns from development sessions.
Auto-managed by [caliber](https://github.com/caliber-ai-org/ai-setup) — do not edit manually.

- **[fix]** `composer phpunit` fails with "not found" if `vendor/` doesn't exist — run `composer install` first, then invoke phpunit directly: `./vendor/bin/phpunit --bootstrap tests/Bootstrap.php tests/src/`
- **[gotcha]** PHP global types (`\PDO`, `\RuntimeException`, `\SessionHandlerInterface`, `\SessionIdInterface`, `\SessionUpdateTimestampHandlerInterface`) must use the fully-qualified `\` prefix inside any namespaced class or test. Omitting it causes PHP to resolve `Detain\SessionSamurai\PDO` instead of the global `\PDO`, producing a `TypeError` at runtime that is hard to trace.
- **[gotcha]** `apcu_fetch()`, `wincache_ucache_get()`, and similar cache-fetch functions return `false` (not `''`) on a cache miss. Cast in `read()` with `(string)(fetch_fn() ?: '')` to always return a string, satisfying the interface contract.
- **[gotcha]** Handler methods that delegate to an inner object (e.g. `$this->handler->write(...)`) and declare `: bool` return type will implicitly return `null` if a `return` statement is omitted — PHP will emit a fatal error or silent type coercion. Always add `return true;` after delegation calls in `write()`, `destroy()`, and `gc()`.
- **[gotcha]** `SemaphoreSessionHandler`: `shm_put_var()` and `shm_get_var()` require **integer** variable keys. Using a string like `$sessionIdKey` silently fails. Define integer constants (`const VAR_DATA = 1; const VAR_TIMESTAMP = 2;`) for all SHM variable slots.
- **[convention]** All `create_sid()` implementations must declare `: string` return type explicitly. Omitting it generates PHP deprecation warnings about interface compatibility with `SessionIdInterface`, which surface as PHPUnit warnings in the test run.
- **[pattern]** For tests of `PhpFastCacheSessionHandler`, inject a `CacheItemPoolInterface` mock via the constructor rather than relying on the no-arg default. The real `\Phpfastcache\Config\ConfigurationOption` may not be installed as a composer dependency, causing `Class not found` errors in CI when the no-arg constructor path is triggered.
- **[pattern]** `PDOSessionHandler` tests can use `new \PDO('sqlite::memory:')` with an in-memory SQLite database — no external database required. Create the sessions table in `setUp()` with `$this->pdo->exec('CREATE TABLE sessions (id TEXT PRIMARY KEY, data TEXT, updated_at INTEGER)')`.
- **[pattern]** For handlers backed by unavailable extensions (APC/APCu not loaded, WinCache, Memcached server unavailable, MongoDB), use `createMock()` against the extension's class rather than making real calls. Tests for FlySystem, SymfonyCache, and PhpFastCache all follow this mock-the-backend pattern.
- **[convention]** `validateId()` must perform an actual existence check (query DB / check cache / check file) rather than returning `true` unconditionally. A blanket `return true` means sessions are never invalidated, which defeats the purpose of the interface method.
- **[gotcha]** Flysystem v4 (`league/flysystem ^4`) removed `FilesystemInterface` — use `FilesystemOperator` instead. Verify with `php -r "require 'vendor/autoload.php'; var_dump(interface_exists('League\\Flysystem\\FilesystemOperator'));"` (must require autoload first or it returns false).
- **[gotcha]** Flysystem v4's `write()` and `delete()` methods declare `void` return type. In PHPUnit 10, mocking them with `->willReturn(null)` throws `IncompatibleReturnValueException`. For `void`-returning mock methods, omit `willReturn()` entirely.
- **[fix]** `assertMatchesRegularExpression()` requires PHPUnit 9+. If tests fail with `Call to undefined method ...assertMatchesRegularExpression()`, upgrade PHPUnit: change `composer.json` to `"phpunit/phpunit": ">=9.0,<11@stable"` and run `composer update phpunit/phpunit --with-dependencies`.
- **[fix]** `MockBuilder::setMethods()` was removed in PHPUnit 9 — replace all uses with `->onlyMethods([...])`. Tests written for PHPUnit <9 will fail with `Call to undefined method PHPUnit\Framework\MockObject\MockBuilder::setMethods()` under PHPUnit 10.
- **[gotcha]** Class declarations cannot use a backslash prefix — `class \PDOSessionHandler` is a PHP parse error. The `\` prefix is only valid in `implements`, `use`, and expression contexts, never in the `class` keyword itself.
- **[env]** When checking class/interface existence from Composer packages via `php -r "..."`, always `require 'vendor/autoload.php'` first. Without it, `class_exists()` and `interface_exists()` return `false` even for installed packages.
- **[gotcha]** Handler methods missing PHP 8 return type declarations (e.g., `open($path, $name)` without `: bool`) generate "Return type should be compatible with SessionHandlerInterface::open()" deprecation notices in PHP 8.x. All `SessionHandlerInterface` method implementations must have matching type signatures.
- **[pattern]** For handlers that depend on optional packages (doctrine/dbal, illuminate/session, influxdb v1 client), check `class_exists()` in `setUp()` and call `$this->markTestSkipped()` if not installed — prevents test failures when optional dev dependencies are absent.
- **[gotcha]** The `// phpcs:ignore PSR1.Methods.CamelCapsMethodName.NotCamelCaps` suppress comment for `create_sid()` must be placed on the line immediately before `public function create_sid()`, not before the preceding `/** {@inheritdoc} */` docblock. In phpcs 4.x, a suppress comment placed before a docblock is not associated with the method declaration and the error is not suppressed.
- **[fix]** When running `./vendor/bin/phpcs` inside a parent project and `phpcs.xml` uses `<exclude-pattern>vendor/*</exclude-pattern>`, all project `src/` files are silently excluded because their absolute paths contain `vendor/`. Symptom: "No files were checked. All specified files were excluded or did not match filtering rules." Fix: change to `<exclude-pattern>*/vendor/*/vendor/*</exclude-pattern>` to only exclude the package's own nested vendor directory.
- **[fix]** PHPStan 2.x removed the `checkMissingIterableValueType` parameter — remove it from `phpstan.neon` if present, or `composer test` (the phpstan step) fails with "Unknown parameter". PHPStan 2.x handles iterable value types automatically.
